# Managed runtime overlay

`yarn omnimux:runtime-overlay --product-commit <full-sha>` is the only supported development-time path for building the Issue #554 `ui-commands-client-action` overlay into vendored DSH runtime tarballs. It validates the pinned upstream SHA in `upstream.json`, clones that source into a temporary directory, extracts the patch with `git show <product-sha>:patches/dsh-<version>/ui-commands-client-action.patch`, checks and applies those frozen bytes, builds the official profile, and calls the pinned upstream `release:pack --family dsh --out <dir>` CLI. It then delegates tarball vendoring to `sync-vendored-runtime.mjs` and runs `check:vendored-runtime`.

The explicit product SHA is required. The working tree is never the patch source. `upstream.json` persists the expected product repository, commit, patch path, and SHA256. `manifest.json` records that same identity alongside the upstream repository and SHA and every vendored tarball's SHA256. The frozen patch bytes are vendored beside the tarballs. `check:vendored-runtime` compares all three records and rejects a missing or changed expected identity, malformed product commit or patch digest, altered frozen patch, mismatched upstream identity, or altered tarball bytes; matching package versions and upstream SHA alone are insufficient.

Use `--work-dir <absolute-path>` only when the same managed build must support isolated L2 QA. The command retains the patched, built source at that path and prints the matching `DSH_SRC` value; it does not copy a runtime into a shared profile. Without `--work-dir`, the temporary build source is removed after vendoring.

The runtime must be vendored before, or atomically with, a plugin declaration that requires `clientAction`; never materialize the new plugin against an unverified older runtime. Roll back the plugin compatibility declaration first, then roll back the runtime, so an older runtime never receives an unsupported declaration. The command does not copy plugin profiles, alter `/Applications`, launch a replacement server, or restart an app. It is a build-chain prerequisite only; a human merge and a separately authorized packaging/install/restart gate remain required before Dev App QA.
